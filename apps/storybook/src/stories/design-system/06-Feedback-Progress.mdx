# 反馈与进度

反馈层级取决于紧急度、影响范围和用户是否需要立即行动。

## Feedback decision table

| 组件 | 适合 | 默认时长/位置 | 不适合 |
|---|---|---|---|
| Inline validation | 单字段问题 | 就地持续 | 全局服务故障 |
| Alert | 当前页面持续性提示 | 内容区顶部/相关区块 | 瞬时成功 |
| Toast | 操作已完成、无需决策 | 3–5 秒，右上或窗口内右上 | 严重失败、长说明 |
| Notification | 后台任务或跨页面事件 | 右侧堆叠，可持续 | 表单字段错误 |
| Modal | 必须立即选择、确认风险 | 居中阻断 | 一般信息告知 |
| Result page/card | 一段任务的最终结果 | 原任务上下文 | 微小状态变化 |

Toast 同时最多 3 条；重复事件合并计数。成功默认 3 秒，信息 5 秒；带恢复操作或重要错误保持到用户处理。所有通知可键盘访问，不自动抢焦点。

## Alert（补充，P0）

变体 info / success / warning / error；结构为图标、标题、说明、可选行动和关闭。错误 Alert 要给“重试/查看详情/更换方案”，而不只显示错误码。

## Modal Dialog（补充并收敛，P0）

| Size | 宽度 | 场景 |
|---|---:|---|
| S | 400 | 简单确认、单字段输入 |
| M | 520 | 权限、设置、上传确认 |
| L | 720 | 多段说明、复杂预览 |

结构：标题、可选说明、正文、底部操作；内边距 24，操作间距 12，最大高度 `viewport - 96`，正文内部滚动。打开后焦点落在标题或首个安全控件；Tab 锁在弹窗内；Esc 可关闭普通弹窗。执行不可逆操作期间不可用遮罩点击意外关闭。禁止嵌套 Modal；第二层详情改为展开或独立页。

确认文案必须说清对象和后果：`删除“售后资料库”？删除后无法恢复。` 危险按钮写 `删除资料库`，不要写“确定”。

## Progress（补充，P0）

- Linear：上传、扫描、下载等有明确总量的任务，显示百分比与阶段。
- Indeterminate：总量未知但系统仍在工作，显示当前动作，不伪造百分比。
- Steps：用户可理解的 3–5 个业务阶段。
- Circular：仅用于空间受限的小型状态，不作为长任务的唯一反馈。

少于 300ms 不显示；300ms–2s 可用轻量 spinner；超过 2s 显示阶段和说明；超过 10s 提供后台运行、取消或稍后查看。取消后说明已完成部分是否保留。

## AI Task State（补充，P0）

统一状态机：`queued → running → waiting_for_user → paused → completed`，异常分支为 `failed / cancelled / partial`。每个状态必须给出可用行动：取消、继续、重试、查看详情、采用部分结果或回到输入。

## Result / Error / Offline（补充）

结果先给结论，再给证据和建议。错误分为用户输入、权限、网络、服务、文件、设备和未知；面向用户的文案不用堆技术码，技术详情可复制。离线时保留可本地完成的能力，并说明哪些动作将排队。
